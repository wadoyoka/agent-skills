# Explainer Video ― 依頼に合わせたナレーションつき動画をコードで作る

依頼ごとに「誰に・何を伝えて・見終わったらどうなってほしいか」を決め（設計メモ `movie/brief.md`）、
それに合わせて構成・言葉・声・見た目・長さを選ぶ。原稿を VOICEVOX で読み上げ、その音声の長さに合わせて
図・画面・字幕を動かした MP4 を作る。動画編集ソフトは使わない。

構成の型・テンプレートの見本シーン・配色は、どれも出発点にすぎない。毎回、設計メモから選び直す。

## 完成物

- `movie/out/<名前>.mp4`（1920×1080・30fps・H.264 + AAC、字幕は映像に焼き込み）
- 作り直せる作業一式が `movie/` に残る（設計メモ・原稿・音声・シーンのコード・確認用の静止画）

テンプレートでできないこと（頼まれたら、作り始める前に伝えて相談する）:

- 縦長（ショート動画）・正方形。テンプレートは横長 1920×1080 前提で組んである。
- 日本語以外のナレーション。VOICEVOX は日本語の読み上げエンジン。字幕だけ他の言語にすることはできる。

## 作業を始める前に聞くこと

### 1. Remotion を使ってよいか（必ず聞く）

Remotion は無料で使える相手が決まっている。判定は**動画を作る側**の立場で決まり、見る人は関係ない。
AskUserQuestion で次のどれかを選んでもらう。

| 立場 | Remotion |
|---|---|
| 個人（個人開発・趣味・個人の仕事） | 無料で使える（商用も可） |
| 社員 3 人以下の営利企業 | 無料で使える |
| 非営利団体（大学・学校・研究室・NPO など） | 無料で使える |
| 社員 4 人以上の営利企業で、Company License を持っている | 使える |
| 社員 4 人以上の営利企業で、Company License を持っていない | **使わない** → HTML 版で作る |
| 分からない | 安全側に倒して HTML 版で作る（あとで Remotion に移す必要はない） |

- 規約は版によって変わる（5.0 で変更予定と告知されている）。Remotion を入れたら
  `movie/node_modules/remotion/LICENSE.md` を読み、上の表と食い違っていないか確かめてから進める。
- 同じ答えは、話者（声）の規約が商用を許すかの判断にも使う。
- 詳細と根拠は `references/licensing.md`。

### 2. 聞き手とゴール（依頼から決めきれないときだけ）

動画の中身は、手順 2 の設計メモで決める。ユーザーに聞くのは、**聞き手**か**ゴール**（見終わって何が分かる・できる
ようになってほしいか）が依頼から決めきれず、どちらに取るかで中身が大きく変わるときだけ。
聞くなら手順 1 と同じ AskUserQuestion にまとめる。ほかの項目（長さ・トーン・配色・声）は依頼から推定して決め、
決めたことを短く伝える。ユーザーが「任せる」「その体で作って」と言ったら、それ以上は聞かずに進める。

## 作業場所: `movie/` で、見える形で作る

- ユーザーの作業ディレクトリ直下に `movie/` を作り、**すべての作業をその中で行う**。
  scratchpad や `/tmp` には置かない。途中の設計メモ・原稿・音声・静止画をユーザーがいつでも開けて、
  あとから自分で直して作り直せるようにするため。
- git 管理下なら `movie/` は未追跡として出る。`node_modules/` や動画が入るので、
  `.gitignore` に足すかどうかはユーザーに聞く（勝手に足さない・コミットしない）。
- 節目ごとに短く伝える: 設計メモができた / 構成ができた / 音声ができた（全体◯分）/ 静止画を確認した / 書き出しを始めた・終わった。

`movie/` の中身（Remotion 版。HTML 版は `src/` の代わりに `index.html` などが入る）:

```
movie/
├── brief.md              設計メモ（聞き手・ゴール・型・長さ・トーン・見た目・声）
├── narration.json        原稿（シーンごとの字幕と読み）
├── timing.json           自動生成: 各文の開始フレームとシーンの長さ
├── public/audio/*.wav    自動生成: 1 文ずつの音声
├── public/shots/*.png    画面のスクリーンショットや、ユーザーから受け取った画像
├── gen-audio.mjs ほか    スキルの scripts/ から写したもの
├── voicevox/             VOICEVOX を立ち上げる場合だけ（docker-compose.yml・Makefile）
├── src/                  シーンのコード（Remotion 版）
└── out/                  確認用の静止画・コンタクトシート・完成した MP4
```

## 制作の流れ

### 1. 材料を集める

事実は一次情報から取る。何が一次情報かは題材で変わる。

| 題材 | 一次情報の例 |
|---|---|
| ソフトウェア（変更点・機能・仕組み） | タグ間の `git log` / `git diff --stat`、リリースノート、設計書、README、コード |
| 製品・サービス・社内の制度や手続き | ユーザーが渡した資料、公式の説明や仕様書、実際の画面 |
| 学習内容・一般的な知識 | ユーザーが渡した教材、教科書や公的機関など信頼できる資料 |

- 数字は数えるか、資料から引く。推測で書かない。ロックファイルや生成物で行数が膨らむときは、
  除いた数字も出して、どちらの数字かを画面に書く。
- 材料がなく自分の知識で書く題材は、確かなことだけを書く。うろ覚えの数字・固有名詞・年号は入れない。
  聞き手に合わせて単純にした説明も、間違いにならない範囲にとどめる。
- 材料が足りず中身が決まらない（売り込む機能の効果の数字・画面・ブランド色がない、など）ときは、何が欲しいかを具体的に聞く。
  材料は推定で作れないので、「任せる」と言われていても聞いてよい。返事を待たずに進められるよう、
  無いときの作り方（数字を使わず場面で見せる、図で描く）を決めておき、届いたら差し替える。

### 2. 動画を設計する → `movie/brief.md`

依頼文と材料から次の項目を決め、1〜2 行ずつ `movie/brief.md` に書く。以降の判断（構成・言葉・声・色・長さ）は
すべてここから引く。依頼に書かれていない項目は文脈から推定し、末尾に「（推定）」と付ける。

| 項目 | 決めること | 書き方の例 |
|---|---|---|
| 聞き手 | 誰が見るか。題材をどれくらい知っているか。何を気にしているか | 小学 4 年生。植物は知っているが「光合成」は初めて |
| ゴール | 見終わったとき、聞き手が何を分かる・できる・決められるか（1 文） | 葉は日光を使って自分の養分を作る、と言える |
| 型 | `references/script-writing.md` の「構成の型」から選ぶ。組み合わせてよい | 仕組み・概念の解説 |
| 流す場面 | どこで・どう見るか（全員で / 各自で / 授業の導入 / 商談の冒頭 / SNS） | 教室のテレビで、授業の最初に全員で見る |
| 長さ | 場面と型から決める（下の目安） | 2 分 |
| トーン | 言葉づかいと雰囲気（ていねい・親しみやすい・元気・落ち着いた・きっちり） | やさしい話し言葉。問いかけを入れる |
| 見た目 | 配色・明るさ・文字の大きさ・動きの多さ | 葉の緑と日光の黄色。文字は大きめ。動きは多め |
| 声 | 話者の雰囲気と話す速さ | 明るくはっきりした声。ゆっくり（1.0） |

長さの目安（指定がないとき）:

| 場面・型 | 目安 |
|---|---|
| SNS・広告、商談や発表の冒頭 | 30〜90 秒 |
| 紹介・概要・授業の導入 | 1〜3 分 |
| 解説・手順・変更点 | 3〜6 分（聞き手が複数なら、聞き手 1 グループあたり） |
| 研修・講義 | 1 本 10 分以内。長くなるなら分けて複数本にする |

- 聞き手が複数いるときは、聞き手ごとに章を分ける（共通の話を先に）。分け方は `references/script-writing.md`。
- 型を組み合わせたときなどに目安どうしがぶつかったら（声の速さ・動きの量・終わり方など）、
  聞き手 → 流す場面 → 型 の順に優先する。
- 書いたら、聞き手・ゴール・型・長さを 2〜3 行でユーザーに見せる。「任せる」と言われていれば、そのまま進める。

### 3. 構成と原稿を書く → `movie/narration.json`

`references/script-writing.md` を読んでから書く。要点:

- 設計メモの「型」の骨組みから始め、ゴールに要らないシーンは削り、足りないシーンは足す。
- 言葉・1 文の長さ・専門用語の扱いは、設計メモの「聞き手」と「トーン」に合わせる（script-writing.md「聞き手に合わせる」）。
- 1 シーン 1 メッセージ。1 シーンの文は 1〜5 文。
- 各文に `sub`（字幕。正しい表記）と、必要なら `say`（読み上げ用。英字や記号をカタカナにしたもの）を書く。
- シーンには `theme`（`light` / `dark` の 2 つの配色）と `part`（見出しの上に出る章名）を付けられる。
  章・聞き手・話の調子が変わるところで切り替えると、区切りが一目で分かる。章がない短い動画は 1 つの配色で通してよい。

書いたら、シーンの並び（見出しの一覧）をユーザーに短く見せる。「任せる」と言われていれば、そのまま進める。

### 4. VOICEVOX を用意する

```bash
node movie/voicevox-speakers.mjs   # つながれば話者一覧が出る
```

つながらなければ、`assets/voicevox/` の `docker-compose.yml` と `Makefile` を `movie/voicevox/` に写し、
`make -C movie/voicevox up` で立ち上げる。初回はイメージの取得に時間がかかるので、そう伝える。
`docker-compose` コマンドが無く `docker compose` だけある環境では、Makefile の該当箇所を読み替える。

### 5. 話者を選び、規約を確かめる

```bash
node movie/voicevox-speakers.mjs --policies     # 全話者の規約の冒頭
node movie/voicevox-speakers.mjs 冥鳴ひまり      # 1 人の規約の全文
```

- 規約は話者ごとに違う。手順 1 の答え（個人か、営利か、企業が関わるか）で使える話者だけを候補にする。
  「非商用のみ」「企業が関わるなら事前確認」と書かれた話者は、その条件に当たる用途では選ばない。
- 候補の中から、設計メモの「声」に合う話者とスタイルを選ぶ。選んだ話者と理由を一行で伝える。

  | 動画の調子 | 向く声 | `speedScale` の目安 |
  |---|---|---|
  | 子ども向け・親しみやすい紹介 | 明るく、はっきりした声 | 1.0〜1.05 |
  | 解説・手順・研修・社外向け | 落ち着いて聞き取りやすい声 | 1.05〜1.12 |
  | 報告・提案（決める立場の人向け） | 落ち着いた、きっちりした声 | 1.1 前後 |
  | 短い告知・宣伝 | 張りのある、元気な声 | 1.12〜1.2 |

  その題材を初めて聞く人が多いほど遅く、慣れた人ほど速くする。
- 規約が求めるクレジット（例: `VOICEVOX:冥鳴ひまり`）を `narration.json` の `credit` に入れる。
  テンプレートは冒頭と最後の画面に自動で表示する。
- OS 付属の読み上げ音声（macOS の `say` など）は使わない。多くは個人的・非商用の利用に限られており、
  人に見せる動画に使うと規約に触れうる。

### 6. 音声を作り、読みを確かめる

```bash
cd movie
node gen-audio.mjs        # public/audio/*.wav と timing.json を作る
node check-readings.mjs   # 英数字を含む文の読み（カナ）を表示
```

読みがおかしい文は `say` を直して `gen-audio.mjs` をやり直す。
実際の音声は聞けないので、最後の報告で「音声は聞いていない」と伝える。
全体の長さが設計メモの長さから大きく外れたら（目安 ±30%）、原稿を削るか足して合わせる。

### 7. 画面の素材を用意する（あれば）

題材に合う素材を選ぶ。本物を見せられるなら、本物がいちばん伝わる。

- ソフトウェアの画面: Storybook があればビルドして、見せたいストーリーを Playwright で撮る（ダイアログは要素だけを撮る）。
  アプリを起動できるなら、その画面を撮る。
- ターミナルの操作: 実際に実行したコマンドと出力をテキストで写し、コード枠（Remotion: `CodeBlock`、HTML: `.codeblock`）で見せる。
  スクリーンショットより文字がくっきりし、大きさも変えられる。
- ユーザーから受け取った画像・写真・ロゴ: そのまま使ってよい。ネット上で見つけた画像は、利用条件を確かめられない限り使わない。
- それ以外（仕組みの図・たとえの絵・グラフ）: シーンのコードで描く（SVG・CSS）。
- 撮った・受け取った画像は `movie/public/shots/` に置く。トークン・パスワード・社内の URL・実名など、見せてはいけないものが
  写っていないか確かめる。見本データ（仮の URL・パスなど）が写ることは最後に伝える。
- 画像の上に強調枠を重ねるときは、**撮ったときと同じビューポート**で測った座標を使う
  （ビューポートが違うと、ダイアログの位置がずれて枠が外れる）。

### 8. 見た目を決め、シーンを書く

- Remotion 版: `references/remotion.md` を読み、`assets/remotion/` を `movie/` に写して使う。
- HTML 版: `references/html-pipeline.md` を読み、`assets/html/` を `movie/` に写して使う。

写したテンプレートを、設計メモの「見た目」に合わせて作り変える:

- **配色**: `light` / `dark` は「2 つの配色の枠」で、中の色は動画ごとに書き換える
  （Remotion: `movie/src/kit.tsx` の `light` / `dark`、HTML: `movie/style.css` の `[data-theme="light"]` / `[data-theme="dark"]`）。
  題材の色（植物なら緑）・ブランドの色（材料から取るか、ユーザーに聞く）・流す場面（暗い会場なら暗め）から決める。
  文字と背景の明るさの差は十分にとる。
- **見本シーン**（`title`・`points`・`flow`・`end`）は動きの書き方の見本。見出し・文言・章名・アイコンは依頼に合わせて全部書き換える。
- **動きの量**: 子ども向け・告知は大きく動かす。研修・報告・提案は控えめにして、読ませる。

どちらの版でも守ること:

- 画面の使い方: 見出しは上 230px まで、本文は 230〜880px、下 200px は字幕のために空ける。
- 要素は「n 文目が始まるフレーム」に合わせて出す。話していることと画面がずれないようにするため。
- 文字は 22px 以上。子ども・年配の人・広い会場で見せる動画は、本文 36px 以上を目安に大きくし、1 画面の文字を減らす。
  字幕（既定 35px）も大きくしてよい（Remotion: `src/Video.tsx` の字幕の `fontSize`、HTML: `style.css` の `#subtitle` の `font-size`）。
  大きくしたら、字幕が 2 行に収まるよう `sub` を短くする。
- 画面の本文には `<ruby>二酸化炭素<rt>にさんかたんそ</rt></ruby>` でふりがなを付けられる（どちらの版もブラウザで描くため）。
  字幕には付けられないので、字幕はひらがなにする。
- 長い英字（パス・ファイル名）は折り返しで崩れやすい。幅を決めて `nowrap` にするか短くする。

### 9. 静止画で確かめてから書き出す

各シーンの「全部出そろったフレーム」を静止画にし、`contact-sheet.sh` で 4 枚ずつ 1 枚にまとめて目で見る。
見るのは、はみ出し・変な折り返し・字幕との重なり・強調枠のずれ。あわせて設計メモに照らして、聞き手にとって
文字が多すぎないか、言い換えるはずの言葉が残っていないかを見る。直してから本番の書き出しに進む。
手順は `references/qa.md`。

### 10. 書き出して、確かめて、置く

- 書き出しは長さによって数分〜十数分かかるので、バックグラウンドで動かし、進み具合が見える形で実行する。
- 終わったら `references/qa.md` の確認（映像と音声の有無・長さ・長い無音・音量）を行い、音量をそろえる。
- 完成品は `movie/out/` に置く。ユーザーが別の場所を指定したらそこへ写す。

### 11. 報告する

- 置き場所、長さ、形式、サイズ
- 設計メモの要点（聞き手・ゴール・型）と、推定で決めたこと
- 確かめたこと / 確かめていないこと（音声を実際に聞いていない、など）
- 使った描画方法と、その規約上の根拠。話者とクレジット
- 写っている見本データなど、流す前に知っておくべきこと
- 直し方: `brief.md` や `narration.json` を直す → `node gen-audio.mjs` → 書き出し直し

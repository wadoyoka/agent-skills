# 構成と原稿の書き方

原稿は `movie/brief.md`（設計メモ）から書く。聞き手・ゴール・型・長さ・トーンが決まっていなければ、先に SKILL.md の手順 2 を行う。

## narration.json の形

```json
{
  "fps": 30,
  "voicevox": { "url": "http://127.0.0.1:50021", "speaker": 14, "speedScale": 1.1, "intonationScale": 1.1 },
  "credit": "VOICEVOX:話者名",
  "scenes": [
    {
      "id": "flow",
      "theme": "light",
      "part": "1｜しくみ",
      "lines": [
        { "sub": "画面に出す字幕（正しい表記）" },
        { "sub": "設定は config.json に保存します。", "say": "設定は、コンフィグ・ジェイソンに保存します。" }
      ]
    }
  ]
}
```

| キー | 意味 |
|---|---|
| `voicevox.speaker` | 話者のスタイル ID（`voicevox-speakers.mjs` で調べる）。規約を確かめてから入れる |
| `voicevox.speedScale` | 話す速さ。設計メモの「声」で決める（SKILL.md 手順 5 の表） |
| `credit` | 話者の規約が求めるクレジット。最初と最後のシーンに自動で出る |
| `scenes[].id` | シーンの名前。音声ファイル名と、シーンのコード（Remotion の `SCENES` / HTML の `data-scene`）に使う |
| `scenes[].theme` | `light` か `dark`（2 つの配色。中の色は動画ごとに書き換える）。章・聞き手・話の調子が変わるところで切り替えると区切りが分かりやすい |
| `scenes[].part` | 見出しの上に出る章名。章名が変わるところで、進み具合のバーに印が付く。章がなければ付けない |
| `lines[].sub` | 字幕。正しい表記で書く |
| `lines[].say` | 読み上げ用。`sub` のままだと読み違えるときだけ書く |

`scenes` の順がそのまま動画の順になる。

## 構成の型

設計メモで選んだ型の骨組みから始める。どれも出発点で、ゴールに要らないシーンは削り、型どうしを組み合わせてよい
（例: 紹介の途中に短い手順を入れる）。タイトルとおわりは、どの型にも付ける。
おわりでは、ゴールに合わせて「覚えてほしい 1 文」か「次にしてほしいこと」を言う。
授業の導入や商談の冒頭のように、動画のあとに続きがある場面では、問いかけや「続きは〇〇で」で終える。

| 型 | 向く依頼 | 骨組み |
|---|---|---|
| 仕組み・概念の解説 | 「〇〇のしくみ」「〇〇とは」 | 問いかけ → 身近なたとえ → 全体像 → 部品を 1 つずつ → 通しで流れを見る → まとめ |
| 使い方・手順 | 「〇〇のやり方」「始め方」「操作の説明」 | できるようになること → 準備するもの → 手順 1…n（本物の画面）→ つまずきやすい所と聞き先 → まとめ・次の一歩 |
| 紹介・売り込み | 製品・サービス・機能・チーム・人の紹介 | 聞き手の困りごと → ひとことで何か → できること 2〜3 個 → 使う場面・効果 → 始め方・お願い |
| 変更点・リリース | 「v1.2 → v1.3 の変更」「今月のアップデート」 | ひとことで → これまでの困りごと → 新しい流れ → 影響と注意 → そのほかの修正 →（技術の詳細） |
| 比較・選び方 | 「A と B の違い」「どれを選べばいいか」 | 選ぶ場面 → 候補 → 観点ごとの比較（表）→ 状況別のおすすめ → まとめ |
| 提案・説得 | 企画・稟議・予算の説明 | 結論（何を決めてほしいか）→ 今の課題 → 提案 → 効果 → 費用・リスク → お願い |
| 報告・振り返り | 月次報告・プロジェクトの振り返り | 結論 → 数字で見る → うまくいったこと → 課題 → 次にやること |
| 授業・研修 | 授業・講座・社内研修 | 今日のゴール → 前提のおさらい → 本題を小分けに（区切りごとに問いかけ）→ まとめ → 練習・次の授業へのつなぎ |
| 事例・物語 | 導入事例・体験談・歴史 | 登場人物と状況 → 困りごと → 転機 → 結果 → そこから分かること |
| 短い告知 | SNS・広告、商談や発表の冒頭（〜90 秒） | つかみ（問いか驚き）→ 要点 1 つ → 根拠 1 つ → 次にしてほしいこと |

効果や数字を言う型（紹介・提案・報告）で、材料に裏づけのある数字がないときは、数字を作らずに
「何がどう楽になるか」を具体的な場面で見せる。

### 聞き手が複数いるとき

共通の話を先に置き、聞き手ごとに章を分ける。章ごとに `part` を付け、`theme` を切り替える。
例（使う人 → 開発する人に向けた変更点の説明）:

```
タイトル（何の動画か・2 つの章の予告）
── 1｜使う人向け（light）──
  章の扉 / ひとことで / これまでの困りごと / 新しい流れ（本物の画面）/ 安心ポイント / 章のまとめ
── 2｜開発する人向け（dark）──
  章の扉 / 数字で見る / 大きな柱 / 仕組みの説明（図・コード片）× 必要な数 / 詳しい資料の場所
おわり（それぞれの聞き手への一言）
```

手順が環境（OS・プランなど）で分かれるときも同じ考え方で、共通の手順は通しで見せ、違うところだけを並べて見せる。
違いが大きく、並べると見づらいなら、環境ごとに別の動画にする。

## 聞き手に合わせる

| 聞き手 | 言葉 | 1 文 | 1 シーンで伝えること | 画面 |
|---|---|---|---|---|
| 子ども | 話し言葉・問いかけ。むずかしい言葉は使わない。使うなら、先に身近な言葉で言ってから名前を出す | 15〜30 字 | 1 つ | 大きな絵と短い言葉 |
| その分野が初めての人（一般の人・お客さん・新しく来た人） | 専門用語は言い換える（「キャッシュ」→「取ってきた値を覚えておく」）。仕組みより「何ができる・何が変わる」から | 25〜40 字 | 1 つ | 本物の画面・身近なたとえの図 |
| 決める立場の人（経営層・取引先の部長など） | 結論が先。細部は省き、判断に要ることだけ言う | 25〜40 字 | 1 つ | 大きな数字・比べる表（裏づけのある数字がなければ、前と後を並べて見せる） |
| 慣れた人・専門家（同業のエンジニア・研究者など） | 用語はそのまま。前置きは短く | 30〜45 字 | 2〜3 つまで | 図・コード片・数字を多め |

- 聞き手の中で知っている度合いがばらつくときは、いちばん知らない人に合わせる。
- 子ども向けの字幕は、その学年までに習っていない漢字をひらがなにする（字幕にはふりがなを付けられない）。
  ひらがなが長く続いて読みにくい言葉（「にさんかたんそ」など）は、画面の本文に `<ruby>` でふりがなつきの漢字を大きく出して補う。
  読み上げは漢字のままでも正しく読むことが多いので、`say` はおかしいときだけ書く。

## 流す場面に合わせる

- **全員で同時に見る**（会議・授業・商談）: 止めて読み返せないので、1 画面の文字を少なくし、要点は口でも言う。
- **各自で見る**（配布・研修・オンボーディング）: 止めながら見られる。写してほしいコマンドや URL は画面に長めに出し、
  同じものを動画の外（README・配布資料）にも置くよう、報告でユーザーに勧める。
- **冒頭や合間に流す**（商談・発表の導入）: その後に人が話す前提で、詳しい説明は入れず「続きを聞きたくなる」ところで終える。
- 冒頭と最後の画面には、話者のクレジットが自動で出る（規約上外せない）。人に見せる場で気になりそうなら、先にユーザーへ伝える。

## 書き方

- **1 シーン 1 メッセージ。** 1 シーンの文は 1〜5 文。1 シーンは 15〜40 秒が目安（短い告知や子ども向けは 5〜20 秒）。
- **ゴールから逆算する。** 各シーンが設計メモのゴールに要るかを確かめ、要らないものは削る。
- **理由を先に。** 「これまでは〇〇で困っていた → だから△△を入れた」の順にすると、聞き手が置いていかれない。
- **事実は一次情報から。** 数字は数えるか資料から引く。ロックファイルや生成物で行数が膨らむなら、除いた数字を使い、
  何を除いたかを画面に書く。分からないことは書かない。
- **画面と文を対応させる。** 「この受け口に」と言うなら、その文の始まりで受け口を強調する。
  文を書くときに、その文で画面の何を出す・光らせるかを決めておく。
- 字幕は 2 行までに収まる長さにする（1 行およそ 45 字）。

## 読み（say）の書き方

VOICEVOX は漢字や数字はおおむね正しく読むが、英字・記号・バージョン番号は読み違えやすい。
`node check-readings.mjs` で英数字を含む文の読み（カナ）を出し、おかしいものだけ `say` を書く。

| 字幕 | say の例 |
|---|---|
| `v0.2.3 から v0.3.0` | `バージョン ゼロてんにーてんさん から ゼロてんさんてんゼロ` |
| `config.json` | `コンフィグ・ジェイソン` |
| `{ code, message }` | `コードとメッセージの組` |
| `..` や絶対パス | `ドットドットや絶対パス` |
| `TanStack Query` | `タンスタック・クエリ` |
| `CI` / `URL` | `シーアイ` / `ユーアールエル` |
| `README` | `リードミー` |

- 中黒（・）や読点（、）を入れると、区切って読ませられる。
- 1 語だけ確かめたいときは `node check-readings.mjs 既定値 照合` のように言葉を渡す。

# HTML Visual Explainer ― 質問を「図解つきHTML解説ページ」で答える

ユーザーの疑問に、**1枚の完結したHTMLファイル**で答える。土台にした `streaming-markdown-guide.html` の
「初心者を置いていかない説明順序」と「各概念に必ず図」という設計を、あらゆるトピックに一般化したもの。

## 完成物

- **単一の `.html` ファイル**（外部依存はGoogle Fontsのみ、そのまま開けば読める）
- **常に日本語**。読み手は「そのテーマの初心者」と想定して書く
- **各概念に最低1枚のインラインSVG図**。言葉だけで終わらせない
- **出力先はユーザーの作業ディレクトリの `docs/` 配下にあるローカルファイル**。ホスティングも公開もしない
- 保存したらパスを伝え、`open <ファイル>`（macOS）でブラウザ表示できると案内する

## 見た目はグラレコ（手描き板書風）で固定

出力の見た目は**常にグラレコ**＝マーカーで手描きした「板書／スケッチノート」風。`assets/template.html`（下地）＋ `references/design-system.md`（装飾ルール）で作る。ユーザーが「グラレコ」と明言しなくても、図解・HTML解説の依頼にはこの見た目で答える。装飾がグラレコというだけで、下の流れと「譲れない約束」（構成・書き方・図の中身）は普遍。

## 制作の流れ

### 1. 構成を設計する（最重要）
書き始める前に `references/structure-guide.md` を読み、アウトラインを作る。
- 登場する概念／部品を洗い出し、**依存関係の順**（Xを知らないとYが分からない → X先）に並べる。これが章順になる。
- 骨格は必ず **HERO（つかみ）→ 01 全体像 → 02..0N 各概念を1つずつ → まとめ表**。
- 短い質問なら「全体像＋2〜3章＋まとめ」で十分。無理に章を増やさない。

### 2. テンプレートを土台にする
`assets/template.html` をコピーして下地にする。`<style>`・スクロール演出・flowアニメはそのまま使う。**この時点で `references/design-system.md` を読み**、グラレコの装飾クラス（バナー・付箋・吹き出し等）と配色の意味づけを把握する。まず `title` / `eyebrow` / `h1`（主役を `.accent` に）/ `lede`（何をどんな順で説明するか＋初心者への一言）と、HERO図を埋める。

**もくじサイドバー（`nav.toc`）と読み進みバー（`.progress`）は触らない。** 中身はページ末尾のスクリプトが各 `<section>` の `.banner`（章タイトル）と `.badge`（番号）から自動生成し、`id` も自動採番する。章を足す＝`<section>` を足すだけで目次も増える。`<ol>` に手でリストを書くと本文とズレるので書かないこと。目次は広い画面でだけ出て、狭い画面では上端の細い進捗バーに切り替わる。

### 3. 各セクションを同じリズムで埋める
1章 = **説明文 →  figure(SVG) →（技術トピックでコードが要点を助ける時だけ）code → note**。
書き方は `references/structure-guide.md` の「初心者ファーストの書き方7則」に従う。要点:
- 新概念は**比喩から**入る。定義から入らない。
- 専門用語 `.term` は**初出で必ず意味を添える**。
- 「こうする」だけでなく**なぜ嬉しいか／怠ると何が起きるか**を書く。
- 段落の最重要文だけ `.hl` で目立たせる（付けすぎない）。

### 4. 各概念に図を1枚割り当てる
`references/svg-guide.md` の早見表で「説明したい関係（流れ／変換／対応／分岐／比較／階層／循環／ツリー／時系列…）」から
図の型を選ぶ。`assets/svgs/svg-catalog.html` をブラウザで開くと部品を見比べられる。選んだ `.svg` の中身をコピーして
`figure` に貼る（**`<svg>` タグごと＝内蔵の `<style>` も含めてコピー**すると、流れアニメがそのまま動く）。
**部品は最初からグラレコで描いてあるので手描き化の変換は不要**。ラベル・数・意味色をトピックに合わせて書き換えるだけでよい。
合う型がなければ素材を組み合わせて自作する（その時だけ `design-system.md` の「図の手描きルール」に従う）。

### 5. デザインシステムを適用する
`references/design-system.md` に従う。**色は意味づけを固定**（青=構造/つなぎ、朱=主役/強調、緑=正しい/安全、赤=問題/危険）。
コールアウトは note / warn / good を使い分け、コードは「言いたい1点」に絞った最小例にする。

### 6. 初心者目線でセルフチェック
- この順で読んで、途中で置いていかれる箇所はないか？ → あれば比喩か図を1つ足す。
- 各概念に図があるか？ 用語は初出で開いているか？ `.hl` は各段落1回までか？
- 図に `role="img"` と `aria-label` があるか？ 赤/緑に記号やラベルも添えているか？

### 7. 保存して案内する
**HTMLは、ユーザーが作業しているディレクトリの `docs/` の中に、通常のファイル書き込みで作成する**（無ければ作る）。
説明的なファイル名（例: `docs/<トピック>-kaisetsu.html`）で保存し、パスを伝える。
必要なら `open <ファイル>` で開くよう案内する。

**ユーザーからの明示的な指示がない限り、ホストに搭載されている共有・パブリッシュ機能は使わない。**
具体的には、Claude Code の Artifact（claude.ai 上にページを公開してURLを発行する機能）、
Codex のクラウド共有、その他アップロード・ホスティング・リンク発行を伴うあらゆる仕組みを指す。
これらは成果物を**外部サービスへ送信＝公開**することになり、キャッシュやインデックスが残りうる。
この解説ページは手元で読むための資料であって、配布物ではない。

判断が揺れたら次のとおり:
- 既定（指示なし）→ `docs/` にローカルファイルとして保存するだけ。共有機能には触れない。
- 「Artifactにして」「共有リンクが欲しい」「公開して」など**ユーザーが明示的に求めたときだけ**共有機能を使う。
- 「HTMLで図解して」「解説ページにして」は共有の依頼ではない。ローカル保存で完結させる。

## 譲れない約束

これらはトピックが変わっても守る。理由まで含めて `references/` に書いてある。
- **常に日本語・初心者ファースト**。賢い友人が隣で順番に教える口調。命令口調や用語羅列を避ける。
- **各概念に必ずインラインSVG図**。外部画像・スクリーンショット・アスキーアートは使わない（拡大で崩れず、読み上げ・翻訳・配色統一ができるのがSVGの利点）。
- **色は飾りでなく意味**。記事内で意味づけを一貫させる。
- **全体像 → 部品を1つずつ → まとめ** の順を崩さない。
- **成果物はユーザーの作業ディレクトリの `docs/` に置くローカルファイル**。ユーザーが明示的に求めない限り、
  Claude Code の Artifact や Codex のクラウド共有といった**ホスト搭載の共有・公開機能は一切使わない**
  （公開＝外部サービスへの送信であり、ユーザーの許可なく行ってよい操作ではない）。

# 構成ガイド ― 初心者を迷わせない説明の順番

このスキルの核。見た目より先に、**「どんな順で説明するか」**が読者の理解を決める。
土台にした `streaming-markdown-guide.html` が優れているのは、まさにこの順番設計だった。
それを一般化したのが以下。技術・非技術どちらのトピックにも使える。

## 大原則

初心者がつまずくのは「いきなり細部」と「順番がバラバラ」の2つ。だから:

1. **まず全体像**。細部の前に、登場人物と流れ“だけ”を掴ませる。地図を渡してから歩かせる。
2. **部品を1つずつ、依存の順に**。Aを知らないとBが分からないなら、必ずA→Bの順。1セクション＝1概念。
3. **最後に1枚へ畳む**。全部を表や図でまとめ、「誰が・いつ・どこで」を回収する。

この3層は、元テンプレの `01 全体像 → 02〜09 各部品 → 10 まとめ` と同じ骨。

## 記事全体の骨格

```
HERO（つかみ）
  ├─ eyebrow：分野タグ
  ├─ h1：主題を一言で（主役を accent 色に）
  ├─ lede：何を・どんな順で説明するかの宣言 ＋「初心者でも追える」の一言
  └─ hero-svg：主役の比喩を1枚で（hero-concept.svg が土台）

01 全体像 THE BIG PICTURE
  └─ 流れ／登場人物だけを図で（flow-pipeline など）。まだ細部に入らない

02..0N 各概念（1章1概念・依存順）
  └─ 各章 = 説明文 → 図(SVG) →（技術なら）最小コード → note

（必要なら）応用・注意・安全性の章
  └─ 「なぜこの選択が良いか」を深掘り。two-paths / compare で対比

NN まとめ SUMMARY
  └─ stack テーブルで全要素を1枚に。前に進める最後の一言
```

章数はトピック次第。短い質問なら 全体像＋2〜3章＋まとめ で十分。無理に増やさない。

## 1セクションの型

各セクションは同じリズムを刻むと読者が安心する。

```
<section class="reveal">
  kicker（01 — 英字ラベル）   ← 章番号。進捗が見える
  h2（この章で何を言うか）
  説明文 p                     ← 比喩で導入。term で用語、hl で最重要文
  figure + SVG + figcaption    ← 各章に最低1枚。言葉だけで終わらせない
  （code）                     ← 技術トピックでコードが要点を助ける時だけ
  note                         ← 落とし穴・大事なルール・うれしい結論
</section>
<div class="seam"><span></span></div>
```

**「各概念に必ず1つの図」**が、このスキルの約束。抽象語は図にすると初心者に届く。

## 書き方7則

1. **比喩から入る**。新しい概念は、まず日常のたとえに置き換える（「担当者」「縫い針」「土台」など）。定義から入らない。
2. **専門用語は初出で必ず開く**。`<span class="term">語</span>` を出したら、その場で日本語の意味を添える。読者に検索させない。
3. **なぜ？を説明する**。「こうする」だけでなく「こうすると何が嬉しいか／これを怠ると何が起きるか」を書く。理由が分かると記憶に残る。
4. **1段落1メッセージ**。最重要の1文だけ `hl` で目立たせる。ハイライトが増えると効かなくなる。
5. **前の章と次の章をつなぐ**。段落末に「では次は〜を見ましょう」の橋渡しを置き、道に迷わせない。
6. **コードと図は最小に**。全部見せない。「言いたい1点」に削るほど初心者には親切。
7. **断定しすぎない**。「絶対安全」より「危険が入りにくい」。誤解を生む過度な断定は `note warn` で補正する。

トーンは、賢い友人が隣で順番に教えてくれる感じ。命令口調や専門用語の羅列を避ける。

## 構成を組み立てる手順

質問を受けたら、書き始める前に紙の上で設計する。

1. **概念を洗い出す**。この説明に登場する「部品／登場人物」を列挙する。
2. **依存関係で並べる**。「Xを知らないとYが分からない」を矢印で結び、トポロジカル順に並べる。これが章の順番になる。
3. **全体像の図を決める**。部品同士の関係は「流れ？対応？分岐？階層？」のどれか。`svg-guide.md` の対応表から全体像用の図を選ぶ。
4. **各章に図を割り当てる**。章ごとに「この概念の関係は何型か」を考え、SVG部品を1つ選ぶ。
5. **まとめ表の列を決める**。「要素／役割／働く場所（or 使いどき）」など、3〜4列で全体を回収できる軸を決める。
6. 以上をアウトラインにしてからテンプレートを埋める。

> 迷ったら「初心者がこの順で読んで、途中で置いていかれないか？」を基準にする。
> 置いていかれそうな箇所には、比喩か図を1つ足す。
